# 免费试玩与付费交付

## 路线 A：免费演示／创作工具

双击 studio.html → 导出 quiz.html。单文件无运行时依赖，可免费发给试测者。可用 GitHub 展示源码与免费教育演示；GitHub Pages 官方明确限制以经营、商业交易或商业 SaaS 为主要目的的网站，因此**正式收费入口不要托管在 GitHub Pages**。这里不提供前端假支付锁。

## 路线 B：兑换码入口（有技术部署要求）

参考实现是单产品、单实例 Python 标准库 + SQLite；不需要 LLM。先在本地练习：

```sh
# 把生成器导出的 quiz.html 放在仓库根目录
python3 server/app.py issue --count 3 --days 30
# 将输出的测试码暂存于本地，不放到公开仓库
python3 server/app.py serve --dev
```

打开 http://127.0.0.1:8787 ，输入测试码。每码仅兑换一次；兑换后同浏览器 Cookie 有效 24 小时，可反复做题；清除 Cookie、无痕窗口或换设备无法恢复，需订单客服核验后补发。30 天是**从发码时算起**的兑换期限，不是购买后 30 天：只发新库存，商品页写明确截止日，不能混淆。

撤销码和其会话：`python3 server/app.py revoke`，按提示输入原码。补发前先撤旧码，再发新码。发码文件及订单映射是敏感经营数据，单独保存、限制访问。数据库只存码与会话的 SHA-256，不存明文。禁止上传数据库、真实兑换码、订单记录。

## 正式上线步骤（未替你开通）

1. 选可运行 Python 长进程、持久磁盘、HTTPS 反向代理且允许商业使用的主机，核对价格、地区可达性、域名/备案及当地适用要求。没有指定或购买任何供应商。
2. 私有目录保存 quiz.html、codes.sqlite；启动 `python3 server/app.py serve --quiz /private/path/quiz.html --db /private/path/codes.sqlite --origin https://你的域名`。服务只监听 127.0.0.1，生产模式 Cookie 必带 Secure。
3. 在你自己的 HTTPS 代理中，将该域名所有请求反代至 127.0.0.1:8787。不要把项目目录当静态网站根目录公开，否则可能泄漏题库、码库存与数据库。服务仅暴露 /、/redeem、/quiz。
4. 配置进程守护、持久磁盘权限、备份与恢复演练。反代设置请求体大小限制、连接/读取超时、访问速率限制，日志不记录兑换码/Cookie。部署域名必须与 --origin 完全一致。
5. 当前内存限流是每连接来源 IP 每分钟 20 次；同一个反代可能让所有用户共用额度，只适合低流量演练。正式业务把可靠的限流放在反代层，评估真实来源与代理信任，不能盲信用户传入的 X-Forwarded-For。标准库 HTTPServer 单线程不是高并发生产框架。
6. 在商家后台确认类目准入、自动发货与外部履约政策后，再把新码库存导入被允许的交付工具，自己完成一笔端到端测试。
7. 对坏码/超时/重复发货准备补发流程，对退款订单撤销兑换权限。日常核对订单和已用库存，监控失败率、到期与磁盘空间。

代码没有订单 API、支付签名验证、退款回调、商家管理界面或自动对账。不要假称自动收款已接通。未来接平台接口时，必须由可信服务器验证订单归属、付款状态、签名与回调幂等性；不能信任前端 paid=true。

## 能防什么，不能防什么

没有兑换码不能从 /quiz 获取页面；一码不能多次兑换，撤销后不能再次获取。**已授权用户依然能保存网页、截图或复制内容**；这不是 DRM，也不能收回已经下载的内容。公开源代码示例本来就是免费的，商业内容应私有部署并提供额外服务价值。

测试没有收集答题内容；接入真实托管与商家工具时，经营者需如实说明日志、会话、订单资料用途与保留期限，并提供售后渠道。
